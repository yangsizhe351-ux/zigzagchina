# ZigZag China Worktree 协作架构

## 为什么不固定六个窗口

当前网站的核心源代码只有少量高耦合文件。六个编码窗口会让多人同时改 `src/main.jsx`、`src/styles.css` 和 `src/content.js`，合并成本会超过并行收益。因此采用“总控 + 两个编码窗口 + 独立审核闸门 + 按需短任务”的动态架构。

默认并行上限：

1. **ZZ-99 Control & Integration（Local）**：保管 `main`、拆任务、合并、回归、更新交接与发布。
2. **ZZ-01 SEO & Static Platform（Worktree）**：处理静态预渲染、真实 404、页面级元数据和构建底座。
3. **ZZ-02 Visual & Performance（Worktree）**：优化现有图片交付、Logo 资源、字号/触控与响应式；不生成新图。
4. **ZZ-05 QA Release（独立 Worktree）**：只读审查开发分支和最终发布候选，给出 `BLOCK / WARN / PASS`；不实现功能、不合并、不部署。

拿到真实旅游数据后，再按需开启：

5. **ZZ-03 Product & Content（Worktree）**：结构化体验数据、询价表、FAQ、政策和真人内容。该窗口等真实业务数据到位后再创建，并替换一个已完成编码窗口，而不是无限增加并行数。

编号用于快速识别职责，不要求连续，也不等于固定窗口数量。`ZZ-04` 预留给以后确有必要的询价转化/分析任务，当前不创建空窗口。

审核窗口可以长期保留但只在闸门时运行，不计入“两个编码窗口”的在制品上限。总控负责调度审核，但不能自己替代独立审核结论。

## 调度原则

任务同时满足以下条件才进入新的 Worktree：

- 有独立交付物和明确完成标准；
- 主要文件与其他活动窗口不重叠；
- 可以独立验证；
- 不依赖尚未确认的业务数据。

否则留在总控台串行完成，或等待依赖信息。限制在制品数量比追求窗口数量更重要。

## 文件所有权与合并顺序

| 窗口 | 主要所有权 | 当前不应修改 |
| --- | --- | --- |
| 总控台 | 协作文档、共享依赖、最终集成与发布 | 不在工作窗口运行期间重做同一功能 |
| 平台与 SEO | HTML、公开路由、构建/预渲染、404、metadata | 旅行文案、视觉资产、体验交互 |
| 视觉与性能 | CSS、既有图片资源、响应式和加载性能 | 路由架构、产品数据、资质事实 |
| 产品与内容 | 页面交互、结构化内容、询价流程 | 构建平台、未经确认的真实数据 |
| QA / Release Gate | 分支 diff、精确 SHA、构建/浏览器证据与审查报告 | 修改业务代码、替开发者修复、合并、推送、部署 |

推荐合并顺序：开发窗口提交 → QA 分支审核 → 总控逐个合并 → QA 最终 `main` 审核 → 用户明确批准上线 → 总控发布 → 线上冒烟检查。若审核发现问题，退回原开发窗口修复，审核窗口不直接改代码。

## 每个任务的开场模板

```text
先阅读 AGENTS.md、HANDOFF.md 和 docs/WORKTREE_OPERATING_MODEL.md。
确认当前分支与工作区后，只处理本任务指定范围。
不要部署，不要修改总控专属文件，不要提交 dist-netlify。
完成后提交到当前 Worktree 分支，并回报：提交 SHA、修改文件、验证命令与结果、残余风险、需要总控协调的共享变更。
```

## 总控验收流程

1. 确认工作窗口提交基于当前基线，读取其变更摘要与验证结果。
2. 将每个开发提交交给 QA / Release Gate，只有 `PASS` 或经用户接受的非阻断 `WARN` 才允许合并。
3. 在 `main` 逐个合并，避免一次混入多个未经验证的主题；每次合并后运行目标检查。
4. 全部合并后生成唯一发布候选 SHA，运行 `npm run check`、`git diff --check` 和浏览器路由/响应式回归。
5. 将最终 SHA 再交给 QA / Release Gate。没有绑定该 SHA 的最终 `PASS`，禁止推送或部署。
6. 更新 `HANDOFF.md`，记录审核结论、发布候选 SHA、未完成项和线上状态。
7. 只有用户明确要求上线时，总控才推送并等待 Netlify；工作窗口和审核窗口永远不直接发布。
8. 发布后验证线上路由、资源、控制台与部署 SHA；失败立即停止后续发布并按回滚规则处理。

## 审核结论规则

- `BLOCK`：存在 P0/P1、构建失败、关键路由/404/表单失败、隐私或公开授权未确认、回归无法复现。不得合并或部署。
- `WARN`：没有阻断问题，但有明确的低风险债务或人工确认项。总控必须记录，涉及业务/公开信息时由用户决定。
- `PASS`：所列范围在指定 SHA 上通过，证据可复现。它只允许进入下一道闸门，不自动授权合并、推送或部署。

## 何时调整窗口数量

- 增加窗口：新任务有独立目录或文件边界，并且不依赖正在变动的接口。
- 减少窗口：两项工作都要改同一个核心文件，或业务数据尚未确定。
- 关闭窗口：任务已经合并、发现前置依赖、或只剩总控可以完成的跨域改动。

这套架构不是固定组织图，而是一个带文件锁、在制品上限和集成闸门的调度方法。
